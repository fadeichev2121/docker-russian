# Docker Desktop на русском

Русский интерфейс **оригинального Docker Desktop**. Установщик создаёт помощник и ярлык **Docker Desktop RU**, который открывает установленный Docker с переводом. Копия Docker не создаётся, файлы приложения и его подпись не меняются.

**Версия 3.0.2 — исправлен порядок запуска Docker.** Node.js вручную устанавливать не нужно. Старый патч `app.asar` больше не используется. Словарь содержит **3 290 фраз**. Запуск полного установщика на реальном Docker ещё требует проверки пользователем; подключение через закрытый канал ранее подтверждено прототипом на macOS с Docker Desktop 4.93.0.

## Установка на Mac

**Скопируйте обе строки в Терминал и нажмите Enter:**

```bash
curl -fL https://raw.githubusercontent.com/fadeichev2121/docker-russian/main/install.sh -o docker_ru.sh
bash docker_ru.sh
```

**В меню введите `1` и нажмите Enter.** Когда появится «Помощник установлен», введите `2` — откроется Docker на русском. При первом запуске Docker нужно предварительно пройти его обычную настройку.

Если обычный Docker уже открыт, сначала самостоятельно выберите **Quit Docker Desktop / Выйти из Docker Desktop** в его меню, затем запустите русский ярлык или пункт **2**. Выход из Docker останавливает его движок: завершите текущую работу с контейнерами перед этим. Простого закрытия окна крестиком недостаточно. Русификатор не выполняет выход за вас.

Node.js, Python и Git вручную устанавливать не нужно. На первом запуске установщик сам подготовит служебные файлы; дождитесь появления меню. Они скачиваются с официального сайта Node.js, проверяются по SHA-256 и сохраняются отдельно для русификатора. Права администратора не нужны.

Позже открывайте **Docker Desktop RU** из своей папки `Программы` (`~/Applications`). Можно добавить этот ярлык в Dock. Терминал после успешного открытия можно закрыть.

> Обычный ярлык **Docker** продолжает открывать обычный интерфейс. Для перевода используйте **Docker Desktop RU**. Это ярлык к установленному приложению, а не его копия.

## Что выбирать в меню

```text
==== Docker Desktop на русском — 3.0.2 ====
1) Установить / обновить русификатор
2) Открыть Docker на русском
3) Статус
4) Удалить русификатор (обычный Docker сохранится)
5) Показать журнал
0) Выход
```

Меню остаётся открытым после выполнения действия или ошибки. Не нужно скачивать репозиторий, искать папку `core` и вручную запускать Python.

Чтобы снова открыть меню, выполните `bash docker_ru.sh` из той папки, куда скачали скрипт. Можно также повторить две команды загрузки выше — так получите актуальный установщик.

## Windows

Нужны установленный Docker Desktop и Windows PowerShell 5.1+. Откройте **PowerShell от обычного пользователя** и вставьте:

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/fadeichev2121/docker-russian/main/windows/install.ps1 -OutFile docker_ru.ps1
powershell -ExecutionPolicy Bypass -File .\docker_ru.ps1
```

В меню выберите **1**, затем **2**. Установщик создаст **Docker Desktop RU** в меню «Пуск». Повторное открытие меню: `powershell -ExecutionPolicy Bypass -File .\docker_ru.ps1`.

**Windows пока экспериментально:** полный запуск с переводом на этой ОС не проверен. Если сборка отличается, помощник сообщит об ошибке и сохранит исходный Docker. Установщик не требует права администратора и не меняет файлы в `Program Files`.

## Linux

Нужен **Docker Desktop**, а не только Docker Engine, и `curl`. Выполните в терминале обычного пользователя:

```bash
curl -fL https://raw.githubusercontent.com/fadeichev2121/docker-russian/main/install.sh -o docker_ru.sh
bash docker_ru.sh
```

Выберите **1**, затем **2**. В меню приложений появится **Docker Desktop RU**. Запускайте установщик **без `sudo`**.

**Linux пока экспериментально:** полный запуск с переводом на этой ОС не проверен. По умолчанию помощник ищет Docker Desktop в `/opt/docker-desktop`. Произвольные сборки, AppImage, Flatpak и Snap не заявлены как поддерживаемые.

## Как убрать перевод

Откройте тот же установщик и выберите **4**. Помощник завершится, ярлык RU будет убран. Запускайте обычный Docker как раньше.

Контейнеры, образы, тома и настройки Docker установщик не удаляет. Помощник не завершает существующий процесс Docker: при уже открытом Docker запуск перевода отменяется с объяснением. Не запускайте перевод во время обновления Docker.

Журналы и файлы помощника остаются в пользовательском каталоге для диагностики. Убранный ярлык сохраняется под именем с суффиксом `.removed-…` для восстановления. Если Docker открыт, перевод отключается, а окно остаётся работать на обычном языке. Маленький фоновый процесс удерживает служебный канал до вашего выхода из Docker: закрытие этого канала тоже может завершить Docker. Автозапуск при входе в систему не включается.

## Что будет после обновления Docker

Помощник хранится отдельно от приложения и подключает перевод при каждом открытии **Docker Desktop RU**. Поэтому обновление не стирает его файлы и повторный патч Docker не требуется.

Будущие версии могут менять устройство интерфейса или запрещать используемый канал. Универсальная совместимость со всеми версиями не обещается: при отказе подключения помощник покажет причину в журнале и отключит перевод, не завершая окно Docker принудительно. Чтобы обновить сам русификатор, повторите команды загрузки и выберите **1**; если русское окно уже открыто, сначала выберите **4**. Перед запуском обновлённого перевода самостоятельно выйдите из оставшегося обычного Docker.

Для новой структуры установки или перемещения Docker повторите пункт **1**. Если установщик использовал ваш ранее установленный Node.js, после его удаления или перемещения также повторите установку помощника.

## Зачем внутри Node.js

Это среда выполнения помощника: он открывает оригинальный интерфейс Docker и подключает перевод. Вручную её настраивать не требуется. Если подходящий Node.js 18+ уже есть, используется он. Иначе установщик скачивает отдельную служебную копию Node.js 24 LTS с [официального сайта](https://nodejs.org/en/download), только исполняемый файл и лицензию. Системные настройки, PATH и npm не меняются.

Автоматическая загрузка доступна на Mac, Windows и Linux для ARM64 и x64. Служебная копия сохраняется в пользовательском каталоге `docker-russian-runtime` рядом с каталогом русификатора из таблицы ниже. После удаления перевода она остаётся вместе с журналами, поэтому повторная установка не требует её скачивать снова. Интернет нужен для первой загрузки, а установка новых файлов русификатора по командам из README требует доступа к GitHub.

## Если возникла ошибка

- **Служебные файлы не скачиваются** — проверьте доступ к `nodejs.org` и GitHub, затем повторите запуск. Вручную устанавливать Node.js не обязательно.
- **Ошибка SHA-256** — загруженный файл не прошёл проверку и не запускался. Для ошибки загрузки повторите установку; для повреждённой сохранённой копии можно установить Node.js LTS с [официального сайта](https://nodejs.org/), открыть новый терминал и повторить установку помощника.
- **«Служебные файлы не запускаются на этой системе»** — сборка Node.js 24 может не подходить старой версии ОС. Можно использовать самостоятельно установленный совместимый Node.js 18+; поддержку такой системы на реальном Docker этот проект не проверял.
- **«Docker Desktop не найден»** — сначала установите [официальный Docker Desktop](https://docs.docker.com/get-started/get-docker/). Docker Engine без графического приложения не подходит.
- **«Официальная подпись Docker не проходит проверку»** — если ранее ставили версию 2.x, восстановите приложение официальным установщиком. Новая версия не исправляет уже повреждённую подпись. Не используйте старый архив 2.1.0 и не сбрасывайте данные Docker для восстановления приложения.
- **Окно осталось английским или не открылось** — вернитесь в меню, выберите **3**, затем **5**. Журнал содержит этап запуска и причину отказа. Для русского интерфейса нужен ярлык RU или пункт **2**, а не обычный ярлык Docker.
- **«Docker уже открыт»** — после завершения работы с контейнерами выберите **Quit Docker Desktop / Выйти из Docker Desktop** в меню Docker, затем повторите пункт **2**. Помощник не выполняет выход за вас.

Если Docker установлен в другом каталоге:

```bash
bash docker_ru.sh --app "/Applications/Docker.app"
```

```powershell
powershell -ExecutionPolicy Bypass -File .\docker_ru.ps1 -AppPath "C:\Program Files\Docker\Docker"
```

Прямые команды без меню: `install`, `launch`, `status`, `restore`, `logs`. Например, `bash docker_ru.sh status`.

## Где хранятся файлы

| ОС | Помощник и журнал |
| --- | --- |
| macOS | `~/Library/Application Support/docker-russian` |
| Windows | `%LOCALAPPDATA%\docker-russian` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/docker-russian` |

Удаление скачанного установщика не удаляет установленный помощник. Для удаления перевода используйте меню, а не удаление случайных файлов Docker.

## Как устроено и что проверено

Node.js запускает оригинальный процесс интерфейса с `--remote-debugging-pipe`. Команды идут через каналы между процессами, без сетевого порта отладки. Перевод применяется только к локальным страницам `app://dd`, не к сайтам входа и внешним страницам. DOM-переводчик пропускает терминалы, код, поля редактирования и известные области логов; значения, введённые пользователем, не переводятся. Полнота словаря и исключений зависит от интерфейса конкретной версии.

[Официальный Desktop CLI](https://docs.docker.com/desktop/features/desktop-cli/) используется для запуска движка и чтения статуса. Сначала помощник запускает процесс интерфейса с каналом перевода, затем запускает движок. При удалении перевода помощник восстанавливает изменённые подписи интерфейса и оставляет окно и канал открытыми до самостоятельного выхода пользователя из Docker. Смена навигации и новые окна обрабатываются повторно.

В версиях 3.0.0–3.0.1 автоматическое завершение dashboard посылало SIGTERM. В Docker 4.93.0 этот сигнал вызывает полный выход и остановку backend, поэтому новое окно закрывалось через несколько секунд. В 3.0.2 это завершение убрано. Проверка исправления в настоящем Docker остаётся за пользователем.

Автоматические проверки охватывают протокол закрытого канала, частичные сообщения UTF-8, предел размера, разрешённые адреса, установку/удаление в временном каталоге без изменений приложения, старое состояние процесса и завершение сигналом. **Это не проверка полноценного запуска Docker Desktop или работы контейнеров.** Реальный сценарий установки, открытия, навигации и удаления пользователь проверяет отдельно. Windows/Linux не проверены на реальных ОС.

Разработчикам:

```bash
node --test tests/*.test.cjs
python3 -m unittest discover -s tests -v
```

Старые `core/patch.py` и `macos/patch.py` оставлены для совместимости истории, но изменение и восстановление ASAR через них заблокировано на всех ОС. Не используйте старые инструкции патча 2.x.
